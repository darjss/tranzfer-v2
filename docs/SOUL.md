# Why this exists

Someone has hundreds of gigabytes of footage. Their editor needs it. Tranzfer should get it there without making either person supervise the connection.

This is a side project. Spend effort on transfers people can trust, then on recurring use and revenue. A correct 100 GB delivery, followed by a 350 GB recovery under deliberate failures, matters more than another architecture layer.

The business targets are $1,000, $2,000 and $3,500 MRR. They are milestones to earn through real use, not reasons to build for imaginary scale.

Keep the code understandable by one person returning after work. Prefer a local change over a new framework. Add machinery when a real workflow needs it.

The interface should explain what happened and what the user can do. Say when file access needs restoring, authorization expired or finalization is still running. Never manufacture testimonials, completion evidence or reliability claims.

[Vision](VISION.md) describes the longer-term product. [Reliability](RELIABILITY.md) defines what we must prove before promising it.
