Code shape tranzfer2

Where code lives and the rules for adding new things. Distilled from 30 repo audits (~/dev/tranzfer2-references/audits/) — specter, t3code, opencode, cap, livestore — filtered to what one product needs. One obvious tool per job, no museum.

02The rules

These are the whole design. Everything else follows.

1. contracts owns the wire. Every operation is Rpc.make in a RpcGroup in contracts. Contracts imports Schema and nothing else — no drizzle, no handlers, no bindings. // t3code, effect-app
2. One composition root. runtime.ts is the only Layer.mergeAll. New service = new file + one line. // opencode app-runtime, minus their DAG machinery
3. Services are Context.Service classes with a static layer. 
class Signing extends Context.Service<Signing, Shape>()("tranzfer/Signing") {
  static layer = Layer.effect(this, Effect.fn("Signing.make")(function*() {
    const config = yield* SigningConfig
    return { presignPart: (args) => ... }
  }))
}
// dfx, livestore, effect-solutions
4. Handlers are thin, and resolve deps once. RpcGroup.toLayer accepts an Effect returning the handler map, so shared services are yielded once at layer build, not inside every op: 
export const TransferHandlers = TransferRpcs.toLayer(
  Effect.gen(function*() {
    const repo = yield* TransfersRepo
    const auth = yield* Auth
    return {
      ListTransfers: () =>
        repo.listRecent(auth.principal.id).pipe(
          Effect.mapError((e) => new TransferUnavailable({ ... })),
        ),
    }
  }),
)
yield* isn't manual wiring — it reads a service from context and the type system tracks it on R. The layer's R is what runtime.ts must satisfy; that is the injection. Same one level down: a repo's yield* D1Client sits inside Layer.effect, runs once at layer build, and every method closes over db. An op can still yield* an extra service inline — it's a context read, not a declaration. Effect.all({ auth: Auth, repo: TransfersRepo }) grabs several in one shot.
Capture the service, not request state. Reading auth.principal inside the op keeps it per-call; hoisting const principal = auth.principal into the gen would freeze one requester's identity into every handler. // specter, t3code
5. Repos are drizzle + nothing else. D1Client resolves once in the layer gen and every method closes over it: 
export class TransfersRepo extends Context.Service<TransfersRepo, {
  listRecent: (id) => Effect.Effect<Transfer[], TransferDbError>
  findById: (id) => Effect.Effect<Transfer, TransferDbError>
  markFinalized: (id) => Effect.Effect<void, TransferDbError>
}>()("tranzfer/TransfersRepo") {
  static layer = Layer.effect(this, Effect.gen(function*() {
    const db = yield* D1Client
    return {
      listRecent: (id) => db.query.transfers.findMany({ /* ... */ }),
      findById: (id) => db.query.transfers.findFirst({ /* ... */ }),
      markFinalized: (id) => db.update(transfers).set({ /* ... */ }),
    }
  }))
}
No BaseRepository<T> — cap's Database.use(cb) is 17 lines and that's the whole pattern. Prefer drizzle's relational API (db.query.transfers.findMany({ where, orderBy, limit })) for reads once relations are declared in schema.ts; db.select() stays for joins and aggregates. Each method maps its own errors to TransferDbError. // cap
6. Errors are Schema.TaggedError, declared per-op. Domain errors live in the service file they belong to; only wire-safe fields on contract errors (code, message, requestId, retryable). Defects never cross. // specter, herdr-ts-sdk
7. The web app's API layer is the official binding. client.ts builds the RpcClient inside the app's Effect layer, runtime.ts freezes a ManagedRuntime into Solid context, and solid-effect.ts carries the ~90-line official example from solid/examples/effect: runEffect adapts an Effect to the AsyncIterable Solid 2 consumes natively — pending goes to <Loading>, failure to <Errored>, a superseded flight interrupts the fiber. effectAction writes mutations as Effect sagas inside action. No [error, value] tuple wrappers — see SOLID-EFFECT-BINDING.md. // omnidraw + solid/examples/effect
8. Uppy is wrapped, not spread. uppy-bridge.ts is the only file importing @uppy/*. It owns the instance, subscribes to events, writes into the store via pure reducers. Components read the store, never Uppy. // pim-agent shape, melty-karts bridging
9. Solid 2 idioms only. createMemo(async) + <Loading>/<Errored> for reads, action/ createOptimistic for mutations, onSettled for lifecycle, two-arg createEffect(compute, apply) for subscriptions. createResource is gone in v2. // specter, wabou, openEtG
10. Forms are hand-rolled field state. Local createStore for values/touched/errors, Effect Schema for submit validation, Kobalte Field for label/error wiring. Our forms are small — email, password, expiry. See §05 for why no lib yet.
11. Per-request fresh MemoMap on the Worker. Effect.provide inside a request leaks the parent fiber's MemoMap — use { local: true } or a fresh Layer.makeMemoMap. Two independent codebases hit this footgun. // effect-app, executor

03Naming

  • Services — kebab-case.ts, tag "tranzfer/Name"
  • RPC groups — one per domain (TransferRpcs, AuthRpcs), not one giant Api once there are two
  • Repos — x-repo.ts
  • Feature folders — own their components/state/styles; no global components/ until reuse is real
  • Tests — x.test.ts beside x.ts

04Growth path

When a services/x.ts crosses ~300 lines it becomes services/x/index.ts plus siblings — cap's Storage/ does exactly this (signed-object.ts, storage-repo.ts beside index.ts). Not before.

05End to end: one feature

"List my recent transfers" traced through every layer. Six files, each doing one job. Names are approximate — the installed types are the authority.

packages/db/src/schema.ts — the table

export const transfers = sqliteTable("transfers", {
  id: text("id").primaryKey(),
  senderId: text("sender_id").notNull(),
  status: text("status").notNull(), // "uploading" | "ready" | "expired"
  createdAt: integer("created_at", { mode: "timestamp" }).notNull(),
})

apps/api/src/repos/transfers-repo.ts — the query (rule 5)

export class TransfersRepo extends Context.Service<TransfersRepo, {
  listRecent: (senderId: string) => Effect.Effect<Transfer[], TransferDbError>
}>()("tranzfer/TransfersRepo") {
  static layer = Layer.effect(this, Effect.gen(function*() {
    const db = yield* D1Client
    return {
      listRecent: (senderId) =>
        db.select().from(transfers)
          .where(eq(transfers.senderId, senderId))
          .orderBy(desc(transfers.createdAt)).limit(20)
          .pipe(Effect.mapError((cause) => new TransferDbError({ cause }))),
    }
  }))
}

packages/contracts/src/transfer.ts — the wire contract (rule 1)

export class Transfer extends Schema.Class<Transfer>("Transfer")({
  id: Schema.String,
  senderId: Schema.String,
  status: Schema.Literals(["uploading", "ready", "expired"]),
  createdAt: Schema.DateTimeUtc,
}) {}

export class TransferUnavailable extends Schema.TaggedError<TransferUnavailable>()(
  "TransferUnavailable",
  { code: Schema.String, message: Schema.String, requestId: Schema.String, retryable: Schema.Boolean },
) {}

export class TransferRpcs extends RpcGroup.make(
  Rpc.make("ListTransfers", {
    success: Schema.Array(Transfer),
    error: TransferUnavailable,
  }),
) {}

apps/api/src/handlers/transfer.ts — thin handler, deps resolved once (rule 4)

export const TransferHandlers = TransferRpcs.toLayer(
  Effect.gen(function*() {
    const repo = yield* TransfersRepo
    const auth = yield* Auth
    return {
      ListTransfers: () =>
        repo.listRecent(auth.principal.id).pipe(
          Effect.mapError((cause) =>
            new TransferUnavailable({
              code: "LIST_FAILED",
              message: "could not list transfers",
              requestId: crypto.randomUUID(),
              retryable: true,
            }),
          ),
        ),
    }
  }),
)

apps/api/src/runtime.ts — the only mergeAll (rule 2)

export const ApiLayer = Layer.mergeAll(
  D1Client.layer,
  TransfersRepo.layer,
  Auth.layer,
  Signing.layer,
  TransferHandlers,
)

apps/web/src/api/client.ts — the client lives in the layer (rule 7)

// TransferClient is a service in WebLayer; effects read it from context.
// RuntimeContext is provided at the app root: <RuntimeContext value={createRuntime(WebLayer)}>
export const listTransfers = Effect.flatMap(
  TransferClient,
  (api) => api.ListTransfers(),
)

apps/web/src/features/transfers/TransferList.tsx — the UI (rule 9)

export function TransferList() {
  const transfers = createMemo(() => runEffect(listTransfers))
  return (
    <Errored fallback={(err, reset) => (
      <button onClick={reset}>Retry: {String(err())}</button>
    )}>
      <Loading fallback={<Spinner />}>
        <For each={transfers()} keyed={(t) => t.id}>
          {(t) => <TransferRow transfer={t()} />}
        </For>
      </Loading>
    </Errored>
  )
}
The flow in one line: drizzle row → repo → handler → Schema boundary → RpcClient → runEffect AsyncIterable → <For>. A failure at any hop lands in the same <Errored> fallback, typed all the way down — and if the memo re-runs mid-flight, Solid closes the iterator and the fiber gets interrupted. Cancellation for free.

06Forms on Solid 2 — the honest state of things

No mature form library supports Solid 2 yet:

library solid-js peer verdict
@tanstack/solid-form 1.33.5 >=1.9.9 allows 2.x by semver, unverified on new reactivity. There's a 2.0.0-alpha line too — also v1-oriented.
@formisch/solid 1.1.0 >=1.6 <2 explicitly excludes v2 (Fabian Hiller's lib)
@modular-forms/solid ^1.3.1 v1 only, superseded by formisch anyway
quoin Field/Form beta.28 a11y wiring only (label/desc/error), not state — useful regardless
STACK.md already gates TanStack Form on adapter verification. For our actual forms (recipient email, password, expiry, workspace settings) a local createStore + Schema validation is ~50 lines and zero risk. Revisit TanStack Form when the v2 adapter is confirmed working.

07Deliberately skipped

  • opencode's LayerNode DAG — bespoke dep-graph for 50+ services
  • effect-app's query DSL + client cache — framework weight
  • specter's event sourcing — the service/layer/Solid patterns are the gold, not the ES machinery
  • quoin as a dependency — 0.3.x, needs a consumer-applied solid patch. Steal its createX+Provider patterns; stay on Kobalte
