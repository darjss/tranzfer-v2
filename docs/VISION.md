# Product direction

Tranzfer moves large production files between people who repeatedly work together. Start with creators sending raw footage to editors. Reliable delivery is the reason to try it; a recurring working relationship is the reason to keep it.

## Sequence

1. Prove web delivery. Upload, recover after interruptions, and give the recipient a usable download. Meet the [reliability gates](RELIABILITY.md) before claiming them.
2. Add desktop transport when recurring use justifies it. Transfers survive renderer loss and resume after restart; the app can stay in the tray.
3. Add a native inbox. Deliver files to an agreed folder with disk-space checks, progress and recovery.
4. Automate repeat relationships. Remember recipients, destinations and delivery rules. Support work returning from editor to creator.
5. Integrate with production tools when a repeated workflow demonstrates the need.

A browser link makes the first exchange easy. Desktop earns its place by reducing work on later exchanges. The eventual action is "send to this person", with the agreed destination and rules already known.

These phases set direction, not a dependency list for the first upload. Ship and learn at each step.

## Scope

Build features that make creator-to-editor delivery more reliable, less manual or valuable enough to pay for. Keep storage temporary and access controlled.

Cloud-drive sync, public file hosting, project management, digital asset management and mounted filesystems are outside this product. Do not build a network, desktop app or automation platform before real transfer usage needs it.
